| 报告 | 内容 | 结论 |

| `docs/stability/real_camera_soak_20260904T105514.json` | 第一轮 24h 实跑（跑满 86417s） | 服务端**零崩溃**：DB 实测 24h 写入 **131,465 条**检测记录；判 FAIL 系 harness 自身 token 过期（12h）未重登 + RSS 测量错误（误报 3.5MB），非服务缺陷，详见下 |
| `docs/stability/real_camera_soak_20260905T*.json`（进行中） | 修复后第二轮 24h 实跑（`--duration 86400 --sample-interval 300`） | 每 5min 增量落盘，完成后 partial=false 即正式报告 |

**长跑哨兵（SoakGuard，`tests/performance/soak_guard.py`）**：针对第一轮 24h"跑完才知道 FAIL"的教训，新增与采样解耦的**心跳哨兵**——秒级心跳探测（默认 30s）、不变量即判（进程存活/HTTP 可达/计数增长/RSS 上下限/P95 上限，硬失败立即即停、软失败连续 N 次即停）、即停告警（webhook + stdout `[ALERT]`）、状态外置（原子写 `--status-file`，随时可查健康度）。故障注入实测：杀死服务进程后 **10 秒内**即停并落 `abort_reason=server_process_exited`；正常 120s 运行零假阳性。自检 `pytest tests/performance/test_soak_guard.py` 8 passed / 23s。机制说明见 `docs/长跑哨兵机制_SoakGuard.md`。

压测期间发现并修复 harness 四处缺陷：① 内存判据 `max/first` 把模型加载一次性台阶（69.7→117.6MB）误判为 68.7% 泄漏——改为稳态窗口对比后实测 12.09%；② 主循环在第一个断言窗口后提前 break（"30min"实际只跑 5min，24h 会 4h 截断）——已修为跑满 duration；③ **24h 长跑 token 过期未重登**（`token_expire_minutes=720`，elapsed ≈11.9h 后 146 个采样全 401 误判失败）——`_authed_get()` 401 自动重登续期；④ **RSS 测量错误**（恒报 3.5MB，服务实际 ~450MB）——改为主进程+子进程树求和并启动时打印校验。
