### 2. 本期现状核实（基于代码逐行验证的业务能力缺口）

| #  | 缺口                     | 现状证据                                                                                                                         | 业务影响                       |
| -- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| G1 | **缺陷图片不留存**            | 检测循环不保存标注图，`image_path` 恒为 `None`（[inspection\_engine.py:L132-170](../edge/src/inspection_engine.py#L132-L170)；DB 列存在但上游不赋值） | 出缺陷后无图可看，无法追溯、无法复检、无法取证    |
| G2 | **告警只有"确认"**           | 事件 API 仅 `/acknowledge`，无误报/漏报标记与人工判定（[routers/alerts.py:L56-68](../edge/src/routers/alerts.py#L56-L68)）                     | 误报无法沉淀为数据，模型迭代无依据，告警噪音无法度量 |
| G3 | **通知仅邮件**              | `notifier.py` 唯一渠道 `send_email()`（[notifier.py:L42-76](../edge/src/notifier.py#L42-L76)）                                     | 产线响应慢，微信/钉钉/飞书工作流无法接入      |
| G4 | **无批次/工单概念**           | 全项目无批次/工单/SKU 数据模型                                                                                                           | 质量数据无法关联生产批次，报表无法按批次出货追溯   |
| G5 | **单摄像头检测**             | 引擎仅单 `active_camera_id` 单检测任务                                                                                                | 多工位产线需部署多套系统，成本翻倍          |
| G6 | **无 ROI 检测区域**         | 无区域配置，全画面检测                                                                                                                  | 背景干扰（传送带边缘、隔壁工位）造成误报       |
| G7 | **无备份与版本化迁移**          | 无 SQLite 备份；schema 仅一次性兼容迁移（[database.py:L153-165](../edge/src/database.py#L153-L165)）                                       | 运行数据资产无保护；后续加表/加列迁移脆弱      |
| G8 | 24h 连续压测未实跑            | 上期遗留 backlog（沙箱限制）                                                                                                           | 长时运行的内存/句柄泄漏未验证            |
| G9 | L4 response\_model 未补全 | 部分路由仍返回裸 dict                                                                                                                | 前后端契约漂移风险                  |

### 3. 本期目标与原则

**目标**：

1. **业务闭环**：缺陷有图可查（G1）→ 告警可判定（G2）→ 误报数据可导出为训练样本（模型迭代闭环）；
2. **生产规模化**：批次追溯（G4）、多工位并发检测（G5）、多渠道触达（G3）、ROI 降噪（G6）；
3. **运营可靠**：数据备份（G7）、24h 压测实跑（G8）、迁移机制（G7）。

**原则**：

1. 上期安全与性能门禁不回退：所有改动过 pytest 全量回归（71+ 用例）+ lint + unit test；
2. 磁盘相关功能（图片留存）必须有配额与自动清理，防止边缘设备磁盘打爆；
3. 所有新功能默认关闭或向后兼容（旧数据 `image_path=NULL`/`batch_id=NULL` 不报错）；
4. 验收标准可量化、可测试，先写测试后写实现（安全项沿用此法）。

### 4. 本期任务优先级

| 级别 | 任务                                          | 依据                                 |
| -- | ------------------------------------------- | ---------------------------------- |
| 高  | 缺陷图片留存（G1）、告警人工判定（G2）、多摄像头并发（G5）、24h 压测（G8） | 追溯与复检是质检系统的立身之本；多工位是产线刚需；压测是上期遗留门禁 |
| 中  | 批次管理（G4）、多渠道通知（G3）、备份（G7a）、schema 迁移（G7b）   | 出货追溯与运营必需，但可分期                     |
| 低  | ROI（G6）、L4（G9）、训练样本导出（1.3）                  | 增强项，资源富余时做                         |

### 总体验收标准（第二期门禁）

1. **追溯闭环**：任意一条缺陷告警 → 能看到现场标注图 → 能给出人工判定（误报/确认/漏报）→ 判定数据可统计为误报率。
