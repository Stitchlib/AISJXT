## 第一部分：深度分析报告

### 1. 项目概览

| 项 | 说明 |
|----|------|
| 系统定位 | 工业（服装）外观缺陷检测：边缘实时推理 + Web 看板 |
| 后端 | FastAPI + SQLite（WAL），模块化于 `edge/src/`（15 个模块 + 12 个路由） |
| 前端 | Vue 3（Composition API）+ Element Plus + ECharts，10 个页面视图 |
| 检测 | `ultralytics` YOLOv8；依赖/权重缺失时降级为标注仿真 |
| 部署 | Docker Compose（后端 python:3.9-slim + 前端 Nginx），CI 为 GitHub Actions |
| 测试 | pytest 7 个测试文件（单元 + 端到端），前端零测试 |

整体评价：项目分层清晰（采集 `frame_hub` / 检测 `detector` / 编排 `inspection_engine` / 持久化 `database` / 推送 `websocket_manager` 职责划分合理），测试有真实端到端覆盖，文档诚实纠偏了早期虚构声明。**但存在多个高危安全漏洞、一处核心业务数据失真、Docker 部署链路断裂、以及随数据量增长必然爆发的性能隐患**，需要按优先级系统性修复后再继续功能迭代。

## 第二部分：开发计划

### 1. 总体目标与原则

**目标**：在不破坏现有可用功能的前提下，把系统从"可演示"提升到"可上产线"：安全闭环、数据可信、性能可长期运行、部署一次成功、体验符合工业场景。

**原则**：
1. 每个阶段结束必须全量回归 `pytest` + 新增测试，问题不过夜；
2. 修复优先于新增：P0 未清零不进入功能迭代；
3. 所有行为变更同步更新 README 与部署文档，杜绝文档再漂移；
4. 兼容性策略：API 已是 `/api/v1`，本次全部为向后兼容修复，不新增 v2。

### 5. 总体验收标准（上线门禁）

1. **安全**：未授权用户（无 token / viewer 角色）无法读取敏感配置、无法控制 WS 指令、无法修改配置与用户；默认密钥/默认密码在生产部署下被环境变量强制覆盖；安全测试用例全绿。
2. **数据可信**：真实推理路径无任何随机指标；缺陷率语义有明确定义并在报表中注明；时间戳统一 UTC。
3. **性能**：100 万行存量下，分页 P95 < 100ms、报表聚合 P95 < 500ms、CSV 导出流式完成且内存 < 200MB；24h 连续运行无内存泄漏。
4. **部署**：`docker compose up -d --build` 一条命令得到可用系统（含模型初始化引导）；CI 含后端测试 + 前端测试/lint/构建 + 双镜像冒烟。
5. **体验**：角色可见性正确；断网重连后状态自愈；全页面错误/空态/加载态齐备。
6. **工程**：pytest + Vitest + ESLint 全绿为合入主干的硬性条件；文档与实现一致。
