## 0. 复核结论速览（先说重点）

系统已经具备**良好的工程骨架与安全基线**：诚实标注降级、RBAC、JWT+stream-ticket 视频流鉴权、增量聚合 O(1) 读取、分块上传、保留清理、Docker 化部署均已落地。但本轮复核用代码级证据复现了既有"验收纪要"声称已闭环的若干项，并发现**两个在当前环境实际失败的回归测试**。

核心风险集中在两点：

1. **业务指标语义正确性**——核心 KPI"不良率 / 检测数"建立在"帧级代理"上，`total_count` 已失去"总检件数"含义（P-01，高）。
2. **真实推理落地可靠性**——真实/仿真模式由环境隐式决定，可在"真实但跑错模型"状态下静默出数；且锁文件未含 `ultralytics`，CI 生产镜像实际无法真实推理（P-02/P-04，高/中）。

> 与既有文档的关系：本计划不推翻既有计划，而是以代码事实**修正其"已验收"结论的偏差**，并补齐"继续开发"所需的细化实施表。建议以本计划为后续开发的权威基线。

## 1. 项目与架构快照（客观基线）

### 1.1 技术栈
- 后端：FastAPI + Uvicorn + Pydantic v2；SQLite（WAL + `synchronous=NORMAL`），单持久连接 + `threading.Lock` 串行化写。
- 检测：ultralytics YOLOv8（惰性导入，缺失降级 `SimulatedDetector`，标记 `is_simulation`）。
- 鉴权：JWT（PyJWT HS256）+ pbkdf2_hmac(SHA256) 加盐；RBAC（admin/operator/viewer）。
- 帧总线：`HubRegistry`/`FrameHub` 共享帧，检测引擎与视频流共用一路帧；引用计数 + linger + 退避重连。
- 实时：`/ws` 鉴权（token / 首帧 auth，5s 兜底），一次性 stream-ticket 取 MJPEG 流。
- 前端：Vue 3 Composition API + Vite + Element Plus + ECharts；`reactive` 单例 store；axios 401 刷新重放；WS 指数退避。
- 部署：Docker Compose（python:3.11-slim 后端 + Nginx 前端）；`requirements.lock.txt` 锁版；GitHub Actions CI。

### 1.2 已具备的扎实能力（肯定项）
- 诚实标注原则：合成画面标"仿真画面"、仿真检测器标"标注仿真"，绝不冒充真实采集/推理。
- 帧总线复用：一台摄像头只开一路采集，多观看端不抢设备。
- 性能机制：增量聚合计数器 `agg_counters/agg_type_shares/agg_trend`，统计/分页 O(1)；CSV 导出流式游标（`export_csv`）。
- 安全面：CORS 默认同源；`/config` 白名单脱敏（secret_key 移除、smtp_pass 掩码）；模型上传分块落盘 + 大小硬限；激活前 `_validate_model_load` 校验。
- 运维：lifespan 装配、`security_warnings` 自检、配置损坏备份 `config.json.corrupt-*`、保留期清理循环。

### 1.3 测试基线（实测）
- 硬件无关子集（`test_units.py` + `test_api.py` + `test_security.py`，39 用例）：**37 通过 / 2 失败**，耗时 210s。
- 全量套件（后台运行，仅排除 `test_camera_discovery.py`）：**>10min 未稳定结束**（含视频流/网络探测/真实模型加载等环境耦合用例），测试绿/红随环境漂移。

## 2. 问题清单（维度 · 根因 · 影响 · 严重度）

> 严重度：高 = 影响核心业务正确性/数据安全/可用性；中 = 规模或运维场景会触发；低 = 当前规模可接受、可维护性/扩展性隐患。
> 每条均附代码证据（文件:行）。

### P-01 【高】核心质量 KPI 语义失真：不良率 = 含缺陷帧占比，`total_count` 恒等于 `defect_count`
- **维度**：功能完整性 / 业务正确性 / 数据语义
- **问题点**：
  - `edge/src/detector.py:119` 真实推理路径 `total = defect_count`（注释将其"合理化"为"缺陷专用模型，总检数以检出框计"）。
  - `edge/src/database.py:394` 聚合层 `defect_rate = defect_frames / total`（含缺陷的帧数 ÷ 总帧数），并在 `get_statistics` 注释明示"缺陷率语义（H3 治理）：以含缺陷的帧占比口径"。
  - `edge/src/routers/reports.py:78` Excel"明细"导出写入 `r["total_count"]`，其值实际等于 `r["defect_count"]`。
  - 前端 `frontend/src/views/QualityReport.vue:136` 趋势图"检测数"实为帧数，不良率折线为帧级代理。
- **根本原因**：
  1. 检测器是"缺陷专用"模型，本就不感知"被检件数"；
  2. 为规避"逐帧随机抽检总数"造假，设计上选了 `total = defect_count`，但**代价是 `total_count` 彻底失去"总检件数"语义**；
  3. 全链路无任何"被检件数"信号源（无生产计数接口、无件分割辅助模型、无产线节拍集成）。
- **影响**：
  - 业务：报表/趋势/告警阈值都建立在"帧级代理"上，与产线实物口径（抽检 N 件、M 件不良）不一致；运营据此做质量决策会**系统性误判**。
  - 用户体验：仪表盘"不良率""检测数"数字看似精确，实际含义失真，易被客户质疑。
  - 技术风险：历史数据口径与未来口径不兼容，后续切换需做数据迁移。
- **严重度**：高

### P-02 【高】真实/仿真模式由环境隐式决定，可"静默跑错模型"
- **维度**：功能正确性 / 运维确定性 / 部署可靠性
- **问题点**：
  - `edge/src/detector.py:133` `build_detector` 仅看 `model_path` 与 `enable_simulation`；当仓库存在 `yolov8n.pt`（COCO 通用权重）+ 已装 `ultralytics` 时，系统以 **COCO 类别（person/car/...）** 跑"真实模型"，输出非服装瑕疵类别却标"真实模型"。
  - 运行期验证：`tests/test_units.py:61` `test_detector_default_is_simulation` 在当前环境**失败**（实际返回 `yolo` 而非 `simulation`）。
  - `edge/seed_model_version.py:54` 将 `enable_simulation=False`，但 `requirements.lock.txt` 不含 `ultralytics` → 实际退化仿真、配置却显示真实（"双盲"）。
- **根本原因**：缺"模型领域校验 / 类目对齐"与显式模式默认；模式完全由"是否存在 .pt + 是否装 ultralytics"隐式耦合。
- **影响**：
  - 业务：在含 COCO 权重环境"真实但错误"地出数，瑕疵类别与业务完全无关。
  - 运维：同一份配置在不同机器上行为不一致，部署不可复现。
  - 技术风险：测试不可移植（见 P-05）。
- **严重度**：高

### P-03 【中/高】Excel 导出全量入内存（M2 OOM 风险复燃）
- **维度**：性能 / 稳定性 / 可扩展性
- **问题点**：`edge/src/routers/reports.py:49` `rows, _ = db.query_results(1, 100_000)` 一次性最多 10 万行进内存；CSV 走流式 `export_csv`（`database.py:436`）安全，Excel 走 `openpyxl` 全量载入不安全。
- **根本原因**：Excel 分支未复用 CSV 的流式/增量纪律；100_000 硬编码上限仍可能在行内含 JSON `defects` 时打爆内存。
- **影响**：大数据量导出进程 OOM、接口 5xx、服务抖动。规模越大越致命。
- **严重度**：中（规模场景）；若 DB 行数大则高

### P-04 【中】依赖锁定与真实推理能力脱节
- **维度**：可维护性 / 部署 / CI
- **问题点**：
  - `edge/requirements.lock.txt` 仅有 `opencv-python-headless==5.0.0.93`，**无 `ultralytics`**；而 `edge/requirements.txt:12` 明确 `ultralytics>=8.0`。
  - `Dockerfile.backend:23` 真实推理仅靠可选 `--build-arg REAL_INFERENCE=1` 安装 `ultralytics`；`.github/workflows/ci.yml:56` 的 `docker-build` 阶段**不传该参数** → CI 产出的生产镜像无 `ultralytics`，真实模式不可用。
  - `tests/test_real_inference.py:17` `pytest.importorskip("ultralytics")` → CI 中该测试被跳过，真实推理路径**从未在 CI 被验证**。
- **根本原因**：lock（落地快照）与 intent（requirements.txt）未同步；Docker 真实推理能力仅靠可选 build-arg，CI 未启用。
- **影响**：文档宣称的"可切换真实模型"在锁装/CI 镜像中实际不可用；真实推理回归无人看护。
- **严重度**：中

### P-05 【中】模型全生命周期测试在当前环境失败（L5 表面回归 + 测试环境耦合）
- **维度**：工程质量 / 测试可信度
- **问题点**：`tests/test_api.py:213` `test_model_version_upload_activate_delete` 在当前环境**失败**（`assert 400 == 200`）。根因：测试上传不可加载的假权重 `b"dummy model weights"`，而 `edge/src/routers/model_versions.py:108` `_validate_model_load` 在已装 `ultralytics` 时执行 `YOLO(path)` 校验 → 激活返回 400。
- **关键澄清**：删除激活版本守卫本身**正确**（`model_versions.py:131-134` 已 raise 400）。失败是测试夹具（假权重）与"有依赖时强制校验"耦合所致，**非产品逻辑缺陷**，但暴露测试不可移植。
- **根本原因**：测试用假权重，未提供可加载权重或 mock；校验在有依赖时执行。
- **影响**：CI 绿/红随环境漂移，复验价值下降，易掩盖真实回归。
- **严重度**：中（质量工程）

### P-06 【中】摄像头凭据模型缺字段 + 明文存储
- **维度**：安全性 / 可维护性 / 数据建模
- **问题点**：
  - `edge/src/models.py` `CameraInfo` 仅有 `id/name/type/source/enabled/status/resolution`，**无 `username/password`**；运行期验证 `CameraInfo(**payload)` 静默丢弃凭据（仅 source URL 内嵌生效）。
  - `edge/src/routers/cameras.py:82-88` 通过 `build_authed_source` 把凭据注入 `source` URL，并存于 `CameraConfig.username/password`（`config.json` **明文**）。
  - 仅 `smtp_pass` 在 `/config` 端点掩码，摄像头凭据无统一掩码。
- **根本原因**：早期 schema 把凭据并入 source URL，未在主数据模型显式建模；缺凭据加密/掩码。
- **影响**：前端无法干净编辑凭据（依赖 source 内嵌，改 source 易致凭据错位）；明文凭据落盘（私有化内部可接受，但非最佳实践）。
- **严重度**：中（安全/可维护性；私有化现场可接受为低）

### P-07 【低/中】告警阈值语义随 P-01 失真
- **维度**：功能完整性
- **问题点**：`edge/src/notifier.py` 评估基于 `defect_rate`（帧级 0/1 代理），告警规则 metric 即 `defect_rate`；阈值难以具备业务含义。
- **根本原因**：同 P-01。
- **影响**：告警在"每帧二值"上可能频繁触发/不触发，阈值难设。
- **严重度**：低/中（随 P-01 解决）

### P-08 【低】统一响应契约（L4 response_model）未全覆盖
- **维度**：代码质量 / 可维护性
- **问题点**：`edge/src/routers/cameras.py` 多个路由返回裸 dict；`routers/config.py` 返回 `_public_config` 裸 dict；`routers/reports.py:15` summary 已用 `response_model`，但其余未统一。
- **根本原因**：增量修复未统一。
- **影响**：契约漂移、文档/类型校验缺失、前端强耦合后端字段名。
- **严重度**：低

### P-09 【低/中】登录限流为单实例内存态
- **维度**：安全性 / 扩展性
- **问题点**：`edge/src/auth.py` `_MAX_FAIL=5` / `_LOCK_SECONDS=600` 为进程内存，不跨 worker/副本。
- **根本原因**：无共享存储（Redis/DB）。
- **影响**：多 worker/多副本部署失效；扩展性受限。
- **严重度**：低（单实例私有化可接受）/ 中（扩展场景）

### P-10 【低】审计日志无保留策略
- **维度**：可维护性 / 数据治理

- **根本原因**：未设计保留期。
- **影响**：库无限增长。
- **严重度**：低

### P-11 【低/中】保留清理日期解析脆弱
- **维度**：健壮性 / 数据治理
- **问题点**：`edge/src/database.py:480` `julianday(substr(timestamp,1,19))` 依赖固定格式前 19 字符；若 timestamp 含时区/毫秒则静默不匹配 → 清理失效。

### P-13 【低】WS 广播全量迭代 + 无背压
- **维度**：性能 / 扩展性
- **问题点**：`edge/src/websocket_manager.py` 遍历全部连接广播。
- **根本原因**：简单实现。
- **影响**：连接数大时每帧 O(N)；当前规模可接受。
- **严重度**：低

### P-14 【低/中】SQLite 单写者吞吐上限
- **维度**：性能 / 扩展性
- **问题点**：`edge/src/database.py` 单持久连接 + `threading.Lock` 串行化所有写；每帧 `insert_result` + `_apply_bump` + `commit`。
- **根本原因**：SQLite 单写者；高帧率产线写入成瓶颈（历史"Postgres 死配置"问题亦指向此）。
- **影响**：高吞吐下写入延迟/堆积；规模化需 Postgres 适配，迁移成本高。
- **严重度**：低（当前规模）/ 中（产线规模化）

### P-15 【低】Excel 导出忽略前端 bucket 选择
- **维度**：功能一致性 / 用户体验
- **问题点**：`edge/src/routers/reports.py:48` 硬编码 `get_trend("day")`；`QualityReport.vue` 可选 day/hour/week/month 但导出恒按日。
- **根本原因**：导出未透传 bucket。
- **影响**：导出与筛选视图口径不一致。
- **严重度**：低

### P-16 【低】全量测试套件运行 >10min（含环境耦合用例）
- **维度**：工程质量 / 反馈效率
- **问题点**：全量 pytest 在当前环境 >10min 未稳定结束；子集 39 用例即 210s（TestClient 每次 import `main` 加载真实模型/预热）。
- **根本原因**：部分用例含阻塞/网络探测；`--deselect` 仅靠人工；模型加载拖慢每个用例。
- **影响**：本地与 CI 反馈慢、易超时。
- **严重度**：低（工程效率）

## 4. 功能优化方案（围绕"完善现有功能、继续开发"）

### 4.1 质量指标语义重建（P-01/P-07）
- 引入"被检件数"信号源：优先**产线节拍计数接口**（PLC/MES 推送 `inspected_items`）；降级方案为**辅助件分割模型**或**配置化每帧件数** `items_per_frame`。
- 指标层区分双口径并在前端明确标签：`frame_defect_rate`（含缺陷帧占比，保留用于实时大屏）与 `item_defect_rate`（不良件数 ÷ 总检件数，业务口径）。
- 仿真模式保留"帧级"口径但**改名诚实标注**，不与业务口径混淆。
- 告警规则 metric 增加 `item_defect_rate` 选项，阈值具备业务含义。

### 4.2 真实模型治理（P-02/P-04）
- 显式 `detector_mode` 默认与覆盖：配置项 `inference_mode ∈ {auto, simulation, real}`，`auto` 时仍按"权重+依赖"决定但**记录决策日志**。
- 模型激活时校验类目与"预期瑕疵词典"对齐（`expected_defect_classes` 配置）；不匹配则**拒绝激活并告警**，避免 COCO 权重冒充服装模型。
- 依赖治理：在 `requirements.lock.txt` 增加 `ultralytics`（或明确分离 optional 依赖组 `[realtime]`）；CI `docker-build` 对 real 变体传 `REAL_INFERENCE=1` 并跑真实推理冒烟。

### 4.3 导出稳健化（P-03/P-15）
- Excel 改用服务端流式：`openpyxl` `WriteOnlyWorkbook` + `query_results` 分块游标；或限制行数并异步生成下载（任务表 + 轮询/通知）。
- 透传 `bucket` 到 `get_trend`，使导出与筛选视图一致。

### 4.4 摄像头凭据建模（P-06）
- `CameraInfo` 增加 `username/password`（或 `credentials` 对象），持久化到独立表或加密字段；前端编辑表单直连模型字段，不再依赖 source 内嵌。
- `/config` 与 `/cameras` 统一掩码凭据；落盘采用对称加密（Fernet）+ 环境变量主密钥。

### 4.5 契约与工程卫生（P-08/P-10/P-11/P-12/P-13/P-14/P-16）
- 补齐 `response_model`；审计日志增加保留期；清理改用 ISO 时间解析；可选 Pinia 渐进迁移；WS 增加房间/背压；写入批处理（`bulk_insert_results` 聚合提交）；测试提速与去环境耦合。

## 5. 技术改进措施（落地路径）

1. **指标语义层重构**：新增领域对象 `InspectionMetric`，区分 `frame` / `item`；DB 增加 `inspected_items` 列与增量累计；聚合层双口径计算。
2. **依赖治理**：`requirements.lock.txt` 增 `ultralytics`（或 optional extras）；CI matrix 增 `real-inference` 作业，docker-build 传 `REAL_INFERENCE=1`。
3. **导出流式化 + 异步任务**：`reports.py` Excel 走 `WriteOnlyWorkbook` 分块；大导出转后台任务。
4. **凭据加密**：`cryptography.Fernet`，主密钥来自 `AIQC_SECRET_KEY` 派生；模型字段补齐。
5. **测试去环境耦合**：模型激活校验在测试中以可加载权重或 mock；`test_detector_default_is_simulation` 固定 fixture config（`enable_simulation` 显式）；新增"无 ultralytics"与"有 ultralytics+COCO"双情景。
6. **SQLite→可选 Postgres 适配层**：抽象 DB 接口，为规模化预留（不强制默认切换）。
7. **保留清理 ISO 化**：`datetime.fromisoformat` 替代 `substr`。

## 8. 风险与回滚

- **P-01 语义变更**会改历史数据口径：采用**双写过渡 + feature flag**，先并行写新旧口径，前端按 flag 切换；回滚即关 flag。
- **P-02 类目校验**可能误拒合法新模型：提供 `expected_defect_classes` 覆盖配置与"强制激活（运维确认）"通道。
- **P-04 依赖变更**增大镜像体积：ultralytics 分组为 optional，基础镜像不含，real 变体单独构建。
- **P-06 加密迁移**：提供明文→密文一次性迁移脚本，保留备份，密钥缺失时服务拒绝启动并给出明确提示。

## 9. 结论

系统骨架扎实、安全基线到位，但**核心业务指标语义**与**真实推理落地可靠性**是当前最该优先治理的两类问题——它们直接决定"系统给出的数是否可信、是否能被客户用于质量决策"。既有 `验收评审纪要.md` 中若干"已闭环"项（L4 响应契约、Excel 导出、真实推理、模型删除守卫）在本轮代码级复核中被证明：要么仍有裸露（L4、Excel），要么在当前环境实际失败（模型测试、detector 默认模式），要么落地链路断裂（lock/CI 缺 ultralytics）。

建议：以本计划为权威基线，按阶段 0→3 推进；其中 **P-01/P-02/P-03/P-04** 应在本迭代优先排期，其余按资源滚动纳入。所有改动均保留 feature flag 与迁移脚本，确保可灰度、可回滚。
